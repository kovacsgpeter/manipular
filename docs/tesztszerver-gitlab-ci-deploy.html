Tesztszerver · GitLab CI + Tailscale + Doppler

Automatikus deploy: nagy gép → GitLab Registry → ThinkCentre

Cél: egy git push után a nagy gép megépíti a Docker image-et és feltölti a GitLab (cloud) Container Registrybe, majd a ThinkCentre-en futó második runner magától lehúzza és elindítja. Az app csak a Tailscale-hálózaton érhető el, routeres portnyitás nélkül. A titkokat (jelszavak, API-kulcsok) a Doppler adja futáskor, repóba nem kerül semmi titok.

0. Áttekintés

git push (main)
   |
   v
GitLab cloud ---- build job (tag: build) ----> nagy gép runnere: docker build + push
   |                                                      |
   |                                                      v
   |                                          GitLab Container Registry
   |                                                      |
   +---- deploy job (tag: deploy) ----> ThinkCentre runnere: docker pull + up -d
                                           (Doppler adja a titkokat futáskor)
                                                          |
                                           Tailscale (serve) --> telefon / laptop

Melyik gépen mi fut? A GitLab a tagek alapján választ: a build tagű runner a nagy gépen, a deploy tagű a ThinkCentre-en van. A .gitlab-ci.yml jobjai a tags: sorral kérik a megfelelő gépet.

2. Tailscale

2.1 Telepítés a ThinkCentre-re

curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up --hostname=homeserver
tailscale ip -4
tailscale status

2.2 Az app kiajánlása a tailneten (tailscale serve)

A javasolt megoldás: a konténer portja csak a 127.0.0.1-en figyel, a Tailscale pedig HTTPS-sel továbbítja a tailnetre. Így nincs indulási sorrend-probléma (Docker vs. Tailscale), és kapsz egy https://homeserver.NEVED.ts.net címet.

sudo tailscale serve --bg 8081
tailscale serve status

Több app esetén használj külön HTTPS portot (sudo tailscale serve --bg --https=8443 8082). A pontos kapcsolókat a Serve dokumentációban ellenőrizd, mert a CLI változhat.

Ne használd a tailscale funnel parancsot: az az app-ot a nyilvános internetre teszi. A HTTPS-tanúsítvány gépneve ráadásul bekerül a nyilvános Certificate Transparency naplókba, ezért ne legyen árulkodó a hostname.

3. SSH (csak a te adminisztrációdhoz)

ssh-keygen -t ed25519 -C "laptop-peter" -f ~/.ssh/id_ed25519
sudo apt install openssh-server
ssh-copy-id -i ~/.ssh/id_ed25519.pub USER@homeserver
ssh USER@homeserver
/etc/ssh/sshd_config.d/10-hardening.conf
PasswordAuthentication no
PermitRootLogin no
sudo sshd -t
sudo systemctl restart ssh

Zárás előtt nyiss egy második SSH-kapcsolatot, és ellenőrizd, hogy beléphetsz. Közben legyen nyitva egy első session vagy a helyi billentyűzet, hogy ne zárd ki magad.

sudo ufw allow in on tailscale0 to any port 22 proto tcp
sudo ufw default deny incoming
sudo ufw enable

A ufw enable előtt győződj meg róla, hogy van helyi hozzáférésed a géphez (monitor, billentyűzet). A Docker által publikált portokra az UFW nem feltétlenül vonatkozik, ezért kötjük az appot 127.0.0.1-re.

Alternatíva: Tailscale SSH (sudo tailscale up --ssh), ekkor nem kell kulcsot kezelned, a belépést a Tailscale identitás hitelesíti.

GitLab SSH-kulcs (opcionális)

Csak akkor kell, ha a saját gépedről SSH-n keresztül pusholsz a GitLabra: a GitLabon Preferences → SSH Keys alatt add hozzá a laptop ~/.ssh/id_ed25519.pub tartalmát. A runnerek HTTPS-en és a job tokennel dolgoznak, nekik nem kell.

4. Doppler (titkok)

curl -sLf --retry 3 --tlsv1.2 --proto "=https" 'https://packages.doppler.com/public/cli/gpg.DE2A7741A397C129.key' | sudo gpg --dearmor -o /usr/share/keyrings/doppler-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/doppler-archive-keyring.gpg] https://packages.doppler.com/public/cli/deb/debian any-version main" | sudo tee /etc/apt/sources.list.d/doppler-cli.list
sudo apt update
sudo apt install doppler
doppler --version
read -rs DOPPLER_TOKEN
export DOPPLER_TOKEN
doppler secrets
doppler run -- printenv DATABASE_URL
unset DOPPLER_TOKEN

Hogyan jut a titok a konténerbe? A deploy job doppler run -- docker compose … formában fut. A Doppler a titkokat környezeti változóként adja a docker compose folyamatnak, a compose.yaml environment: listája pedig átadja a kiválasztottakat a konténernek. Lemezre nem íródik titkos fájl.

Rotálás: ha a tokent lecseréled, generálj újat, írd át a GitLab változót (5.3), majd töröld a régit a Doppleren. A Doppler saját GitLab-integrációját (titkok szinkronizálása GitLab változókba) szándékosan nem használjuk, mert az a titkokat átmásolja a GitLabba.

5.3 CI/CD változók

A registry-hozzáféréshez nem kell semmilyen deploy token vagy jelszó: a job a saját CI_REGISTRY_USER / CI_REGISTRY_PASSWORD (job token) változóit használja, ezek a job végén érvénytelenek lesznek. Az ingyenes csomagban a saját runnerek futása nem fogyasztja a GitLab gépperceket.

6. Runnerek telepítése és regisztrálása

Mindkét gépen (nagy gép és ThinkCentre) ugyanaz a lépéssorozat, csak a token és a tag különbözik.

curl -L "https://packages.gitlab.com/install/repositories/runner/gitlab-runner/script.deb.sh" | sudo bash
sudo apt install gitlab-runner
sudo rm -f /home/gitlab-runner/.bash_logout

A .bash_logout törlése ismert Ubuntu-hibát előz meg (a shell executor jobja „Process exited with status 1" hibával állhat le).

sudo gitlab-runner register --non-interactive --url https://gitlab.com --token RUNNER_TOKEN --executor shell --description "builder"

A ThinkCentre-en a --description "homeserver-deploy" legyen.

sudo usermod -aG docker gitlab-runner
sudo systemctl restart gitlab-runner
sudo gitlab-runner verify
sudo gitlab-runner status
Biztonság: a docker csoport gyakorlatilag root-jogot ad. Ezért a runnerek projekthez kötöttek, protected módban futnak, és a deploy csak a main ágról indulhat. Ne regisztráld a runnert olyan projektekhez, amelyekben nem bízol.

7. Fájlok a repóban

Az app Dockerfile-ja a repó gyökerében van, a konténer belül a 8080 porton figyel (ezt igazítsd a sajátodhoz). A két új fájl a gyökérbe kerül.

compose.yaml
services:
  web:
    image: ${APP_IMAGE}:${IMAGE_TAG}
    ports:
      - "${BIND_IP}:${APP_PORT}:8080"
    environment:
      - DATABASE_URL
      - SECRET_KEY
    restart: unless-stopped

Az environment: alatti nevek (érték nélkül) a Doppleren lévő titkok nevei. Adatot tartós tárolásra named volume-ba tegyél, ne relatív könyvtárba, mert a runner munkakönyvtára minden jobnál törlődik.

.gitlab-ci.yml
stages: [build, deploy]

variables:
  APP_PORT: "8081"
  BIND_IP: "127.0.0.1"
  COMPOSE_PROJECT_NAME: myapp-test

build:
  stage: build
  tags: [build]
  rules:
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
  script:
    - echo "$CI_REGISTRY_PASSWORD" | docker login -u "$CI_REGISTRY_USER" --password-stdin "$CI_REGISTRY"
    - docker build --pull -t "$CI_REGISTRY_IMAGE:$CI_COMMIT_SHORT_SHA" .
    - docker push "$CI_REGISTRY_IMAGE:$CI_COMMIT_SHORT_SHA"
  after_script:
    - docker logout "$CI_REGISTRY"

deploy:
  stage: deploy
  tags: [deploy]
  needs: [build]
  resource_group: teszt
  environment:
    name: teszt
  rules:
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
  variables:
    APP_IMAGE: $CI_REGISTRY_IMAGE
    IMAGE_TAG: $CI_COMMIT_SHORT_SHA
  script:
    - echo "$CI_REGISTRY_PASSWORD" | docker login -u "$CI_REGISTRY_USER" --password-stdin "$CI_REGISTRY"
    - doppler run -- docker compose pull
    - doppler run -- docker compose up -d --remove-orphans
    - docker compose ps
    - curl -fsS --retry 15 --retry-delay 2 --retry-connrefused -o /dev/null "http://127.0.0.1:${APP_PORT}/"
  after_script:
    - docker logout "$CI_REGISTRY"

Mit csinál?

  • Az image tagje a commit rövid hash-e, így mindig tudod, mi fut.
  • A resource_group miatt két deploy nem fut egyszerre.
  • Az utolsó sor egészségellenőrzés: ha az app 30 mp alatt nem válaszol a / címen, a job elbukik. Ha az appnak van /health végpontja, azt írd be.
  • A DOPPLER_TOKEN a GitLab változóból jön, a Doppler CLI magától felismeri.

Visszaállítás régi verzióra

Nyiss meg egy régebbi, sikeres pipeline-t, és a deploy jobon nyomd meg a Retry gombot. A régi commit hash-e szerinti image-et indítja újra. Ehhez az kell, hogy a cleanup policy még ne törölje a régi taget.
